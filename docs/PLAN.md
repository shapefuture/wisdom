# Wisdom Foundry delivery plan
Reference: Wisdom Foundry 11 (2026-11-03), all 22 sections, plus AAA v7.1. Source blueprint is docs/architecture.md.
Acceptance bar is the actual specification and runnable scenario/contract tests; no invented benchmark victory.

1. FOUNDATION: freeze contracts, rights, epistemic types, isolated workcells, task authority.
2. STORAGE: versioned SQLite/FTS, exact originals, signed evidence edges, hash-chained event journal, CAS/idempotency, export/deletion.
3. EVIDENCE: authorized text/SRT/VTT intake, exact offsets/time anchors, coverage, faithful claims, arguments, interpretations, review and corrections.
4. THEORY: scoped regularities, mechanisms, negative cases and source-family independence.
5. INVENTION: independent problem dossier, stuck diagnosis, structural transfer, reframes, explicit mismatch, prior-art status, adversarial tests and no-match.
6. LEARNING: human decision contracts/VOI, sealed predictions, experiments, observations, causal limits, conditional skill support/authorization.
7. MEMORY: permission-aware multi-lens/context retrieval, lineage, prospective expiry/silence, human-owned goals and TRACE, resumable jobs/budgets.
8. WORKBENCH: accessible web UI for source evidence, problem/discovery, decisions/experiments, learning, review, exports, audits.
9. ASSURANCE: independent critic, architecture/swap checks, injection/rights tests, concurrency/retry/recovery tests and full HTTP scenario.
10. DELIVERY: reproducible CLI/CI/container/start instructions, immutable generation identity/rollback evidence, GitHub candidate.
11. EMPIRICAL: preserve Gate 0–5 experiments A0–A6 in tracker. Human panels, gold annotations, licensed live media and live provider quality require real access and participants; automated fixtures do not accept these criteria.

The authoritative task states, acceptance criteria, evidence and blockers are in .delivery/tracker.json, operated by tools/tracker.py. This document defines sequence and scope only.
